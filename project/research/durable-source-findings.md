## Substrate conclusions for host design

1. **Good substrate match, not turnkey runtime.** The committed-state Session and durable task scheduler look suitable for host-owned agent persistence and local interactive projection. The host must own process lifecycle and a client/control plane.
2. **Attach means projection over committed state.** Durable watches do not supply auth, replay history for reconnect, or application delivery semantics. Clients should receive a fresh snapshot and host-defined revision/correlation data.
3. **Ownership is lifecycle, not permission.** Use a separate host authorization model and explicit assignment/work-item ownership. The durable task tree alone does not solve worker replacement or stale result routing.
4. **Recovery replays code, not external transactions.** Design all effects with idempotency keys, polling/reconciliation or explicit uncertain state. A checkpointed intent/effect/outcome sandwich preserves recovery evidence but not atomic external effects.
5. **A single-writer host boundary is mandatory.** The Session line only serializes calls within one opened process. No distributed lock / multi-writer guarantee is established here.
6. **Pin a release before implementation.** Current README calls the interface experimental; the inspected main SHA is evidence only, not a compatible npm package version. Latest HEAD's selected implementation diff means revisiting this review against the eventual dependency pin is warranted.
