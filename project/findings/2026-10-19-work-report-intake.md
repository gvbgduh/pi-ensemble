## Design implications supported by concrete cases

- Preserve persistent direct specialist access after task completion and sibling replacement (CS-02), without retaining oversized active contexts forever.
- Make direct human steering and its driver notification durable; distinguish admission, semantic reconciliation and compliance (F-03/04).
- Separate reply/thread correlation from a caller's waiting timeout; track explicit result obligations so local prose is not mistaken for delivered output (F-05/06).
- Fence actual tools/workspaces during replacement, not only alias pointers (CS-01/03); isolate writers and use one aggregate tracker maintainer (F-09/10).
- Keep independent reviewer access to primary evidence; do not mistake necessary verification overlap for waste (F-08).
- Reconcile live/offline changes before dependent dispatch. Retain human offline updates as a gate, not an assumption inferred from an API check (F-16, skill contract).
- Use deterministic permissions/approvals for effects; Jev advises with neutral rubrics and visible failure, never authorizes. Local Laya outcomes do not measure hosted Jev quality (F-14/15).
